What sheprd adds to herdr

Organised by project, not by machine.

▾ ★

One list across machines

Projects collect their agents from every machine in one place. Drag a workspace in or out, or let a name rule place it. Everything else lands in Other.

● ○ ⚑

Attention you control

Agents that finished or are waiting stay unread until you look. Keep one active on purpose, dismiss the rest, and jump to the next that needs you with prefix+u.

ctx 581k

Peek, don't clutter

Hold the peek key to see idle time, context size, today's tokens per project and each machine's latency. The rest of the time the sidebar shows status and topic only.

▰▰▰▱▱ 3/5

What each agent has been doing

A panel on the right for the agent you're looking at: a short summary of its work (any agent, any model you plug in), the questions it waits on, its to-do list, and each task it handed to subagents with its dev, review and browser-check stages. No need to read the transcript.

✗ PR #7

PR, checks and deploys

Plug in a command per forge or pipeline and every workspace shows its PR, checks and deploy state. Red CI counts as needing you.

board

Every agent on one page

A status board across machines, grouped by project, those that need you first, with what each is on and what it's asking.

3 ms

A server that feels local

What you type on another machine shows at once, like mosh. Switching workspaces shows the last screen immediately, and machines reconnect seconds after Wi-Fi comes back.

laptop → dev

Move an agent, keep the conversation

Closing the laptop? Move a Claude Code agent to the server: sheprd checks the repo there, carries your uncommitted changes as a commit or a patch, and resumes the same conversation on the other machine.

plan.md

Documents in your editor

Ctrl+click a Markdown path an agent printed and it opens in your editor, in a split next to that agent, on its machine. Agents can open the plans they write for you too.

laptop ⇄ server

Agents talking to agents

sheprd msg lets an agent on one machine ask an agent on another, even when the server can't reach your laptop.

SHOP-212

Your tracker, one click away

Teach sheprd what your issue ids look like. Ctrl+click one in any agent's output and it opens in a scrollable markdown reader.

sheprd msg

Ask the agent on the server. Tell the one on your laptop.

Any agent that can run a shell command can take part. Every message says who sent it and how to reply.

  • Laptop to server goes direct, over the SSH link sheprd already uses.
  • Server to laptop waits in a small queue on the server. sheprd collects it while it's open, so the server never gets access to your machine.
  • Guardrails: the receiver is told the message comes from another agent, and to ask you before anything destructive or public. A rate limit stops two agents from ping-ponging.

References

Plug in your own tracker.

sheprd doesn't know your tracker. You describe what a reference looks like and the command that prints one. GitHub issues, Linear, a folder of markdown: anything with a command line works.

  • Ctrl+click a reference in any agent's output to read it.
  • The reader turns front matter into a header and renders the markdown. Scroll with the wheel, arrows or PgUp/PgDn; Esc closes.
  • Mentioned: right-click an agent to see the references it talked about.
# ~/.config/herdr/sheprd-refs.toml
[[refs]]
name    = "issues"
pattern = "#\\d+"
command = "gh issue view {id}"

[[refs]]
name     = "shop"
pattern  = "SHOP-\\d+"
ids_from = "~/notes/tasks"   # only ids that exist
command  = "cat ~/notes/tasks/{id}.md"
Defaults, no config needed
